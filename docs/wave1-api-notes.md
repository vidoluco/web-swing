# Wave 1 API notes

Written by the lead on 29/09/2026 from the reports of the three wave 1 agents, after merging them into main. Wave 2 agents read this first.

### feat/core (merged into main)
Files: src/systems.js (class Systems), src/systems-list.js, src/events.js (Events), src/save.js (Save), src/hud.js (Hud), src/cities.js (CITIES), src/mapselect.js, test/core.mjs, test/citycards.mjs. Edited: src/main.js, src/minimap.js, src/input.js, src/osmcity.js, index.template.html, test/harness.mjs, README.md.

SYSTEMS. A system is src/<name>.js with `export function create(game) { return { name, init?(), update(dt), onCityChange?(id), dispose?() } }`. Add ONE line to src/systems-list.js: `() => import('./name.js'),`. The array order is the update order. (The lines are lazy imports so each system is exactly one line; esbuild inlines them into game.js, verified.) Lifecycle: create() runs for all systems first (create must not touch other systems), then init() on each, then onCityChange(cityId) on each, then update(dt) every tick. update runs after player/traffic/drinks/voice/sfx and before city.update, minimap.draw, hud.update and input.endFrame, so systems can read input.state.*Pressed and set minimap markers the same frame. A system that throws is logged once via console.error and keeps being called. Runtime API: `game.systems.add(system)` (starts it at once: init, then onCityChange), `remove(name)` (calls dispose), `get(name)`, `list`. `game.systems` is not in the original contract, it is an extra.

GAME. game = { scene, camera, renderer, params (URLSearchParams), cityId, city, player, hero, traffic, drinks, drunk, voice, input, events, actors: null, hud, save, minimap, sfx, time, rng, systems } plus the old hooks (advance, simulate, state, shot, goTo, aerial, rig, setInput, look, pointIn, pilot, stopPilot, enterCar, exitCar, driving(), ready). `state()` gained `city`. `game.time` is a number, game seconds, advanced by tick (so advance/simulate move it). `game.rng()` is mulberry32 in [0,1), seed from `?seed=N`, default fixed 20260929, so runs are deterministic unless a test passes a different seed. The actors agent must create `game.actors` in main.js at the line marked PLACEHOLDER (src/actors.js does not exist yet).

EVENTS. `game.events.on(name, fn)` returns an off function. `emit(name, payload)` calls every listener and logs a throwing one without stopping the rest. The core emits `car:stolen {car}` (in enterCar) and `city:change {id}` (once at boot, after systems.start()). All other event names (hit, actor:down, actor:tied, crime:start, crime:end, wanted, busted, respect, mission:start, mission:end, player:down) are for the systems to emit; they are listed in the README.

CITY SWITCHING. It is a page reload (`?city=id`), so onCityChange and city:change fire once per page load. There is no in-page switching.

INPUT. `game.input.state` adds attackPressed (left click or KeyJ), throwPressed (KeyQ), tiePressed (KeyC), interactPressed (KeyG), pausePressed (KeyP). Left click still sets swing/swingPressed as before, so systems decide (for example ignore swing when they treat the click as an attack). The core itself only acts on pausePressed (it releases the pointer lock, which shows the pause screen). `setInput()` overrides now default the new fields to false.

HUD. `game.hud.add(id, spec)`: spec is an Element, or `{order, el?, render?(el, game)}`. It returns the container div, which lives in the #hud-panels row (flex wrap, CSS order = `order`, an Element spec has order 0). Class `.hud-item` styles it as a dark pill, and an empty item is hidden. render runs at ~10 Hz and once on add: update text in place, do not rebuild. `hud.remove(id)`, `hud.toast(text, seconds = 1.8)` (the toast shares one line with the objective and hides it while it shows), `hud.setObjective(text or null)`. #say (Voice) and #hint (car hint) now sit in the #hud-bottom column. Layout is checked at 1280x720, 800x600, 390x844 and 844x390: no overlaps, text at 13 px or more.

MINIMAP. `game.minimap.setMarkers(ownerId, [{x, z, color, shape: 'dot'|'ring'|'square', label?}])` replaces that owner's set, and `[]` or null clears it. Markers off the map stick to its edge (slightly faded, no label). Labels are drawn at 13 CSS px.

SAVE. `game.save.get(key, fallback)` and `set(key, value)`. All keys live in one JSON object in localStorage `webswing.v1`. get returns a fresh copy. `set(key, undefined)` deletes. Every access is in try/catch and falls back to memory. The core stores `city` (last chosen or played).

CITIES. src/cities.js exports `CITIES = { bucharest, brasov, center }`. Fields: label, tagline, image, cardView (camera for the card screenshot), spots [[name, x, z]] for keys 1-9,0, waypoints (the ?demo route, falls back to [[0,0]]), spawnFacing [x, z] or null, note (Brașov's TODO). `center` is a hidden alias (menu:false) so the old `?city=center` still works. An unknown id shows "Mappa sconosciuta" with a Cambia mappa link. OsmCity: `OsmCity.load(base, scene, envMap, textures, onProgress, spawnFacing)`, `city.cityId` (last segment of the base path), `city.origin` (index.json origin {lat, lon}), `city.groundAt(x, z)` (returns 0; the terrain agent replaces the body). `finish(facing)` now takes the spawn-facing point from the config instead of the hard-coded Parliament. goTo(i) is a no-op when the city has no spot i. To add a city: build data into public/city/<id>/, add it to CITIES, run `PORT=n node test/citycards.mjs <id>` (needs `cardView`, otherwise it uses a default aerial), then `node build.mjs`.

MAP SELECTION. Cards are plain links `?<other flags>&city=<id>`, so nothing heavy loads before the choice. A plain URL with no `city`, no `demo` and no `shot` shows the selection. Pause screen: "Cambia mappa" goes to the selection and drops city, demo and shot. test/harness.mjs `open()` appends `city=bucharest` when the query has no city, so existing tests never see the selection.

TESTS. Run `node build.mjs`, then `PORT=<port> node test/physics.mjs` and `PORT=<port> node test/core.mjs`. core.mjs tests systems by adding probe systems at runtime, so it works while the list is empty and keeps working once real systems are added.

### feat/brasov-data (merged into main)
RUNTIME CONTRACT for the next agent.
Files: public/city/brasov/index.json has "dem": {file:"dem.bin", w:936, h:1034, x0:-6915, z0:-8550, step:15, min:-80.7, max:870.04, base:591.05}. dem.bin is w*h Float32 little endian, row-major, sample [j*w+i] at x=x0+i*step, z=z0+j*step (rows increase to the south, columns to the east). Heights are metres relative to the ground at the origin. base is the origin's elevation above sea level.
groundAt(x,z) must be bilinear, clamped at the edges: u=clamp((x-x0)/step,0,w-1), v=clamp((z-z0)/step,0,h-1), i=min(floor(u),w-2), j=min(floor(v),h-2), then bilinear between nodes (i,j),(i+1,j),(i,j+1),(i+1,j+1). A city without "dem" is flat and returns 0. The reference implementation is tools/dem-lib.mjs (exports loadDem(dir, meta) -> {meta, data, groundAt}, demFromBuffer, bilinear).
Chunk schema is unchanged. Buildings [style,colour,y0,y1,roof,seed,outer,holes,name] now carry final terrain heights (y0 and y1 are absolute, relative to the origin height). Roads, trees, pois, greens, water and rails keep x,z only and must be draped with groundAt. lod.bin boxes also use the baked y0/y1. ground.png is a plain land use map with no baked lighting.
index.landmarks for Brasov: [{key,name,x,z,y}] (y is the ground height there). Keys: piata-sfatului, biserica-neagra, strada-sforii, turnul-alb, bastionul-tesatorilor, poarta-schei, gara-brasov, parcul-central, poiana-brasov, tampa-summit, tampa-telecabina-sus, telecabina-brasov-jos, scritta-brasov. Bucharest keeps the old [{name,x,z,h}] format. Nothing in src/ reads landmarks yet.
Key numbers (game x,z, ground y): Piata Sfatului (30.9,60.1,-3.7); Biserica Neagra (-42.3,186.9,4.0); Strada Sforii (-8.2,349.4,5.0); Turnul Alb (-172.9,-18.1,39.7); Bastionul Tesatorilor (19.8,640.6,27.1); Poarta Schei (-182.0,392.2,8.5); Gara Brasov (1936.4,-2044.3,-25.3); Parcul Central = Parcul Nicolae Titulescu (253.1,-374.9,-10.2); Poiana Brasov centre (-2530.2,5085.3,434.9); Tampa summit (327.7,943.3,349.0); Tampa cable car top station (640.9,785.0,349.3, roof 361.5). Sign BRASOV: OSM node at (370.6,892.4,331.5), slope 32.6 degrees facing compass 345 (the town lies at 337); recommended row centre (404.3,883.1,330.8), letters face (x -0.266, z -0.964), read along (x -0.964, z 0.266). Bear streets: Cibinului, Plaieșilor, Petofi Sandor (Schei), Alunis, Fragilor (Racadau), entry points and grades are in docs/brasov-landmarks.md, together with a ready SPOTS array for the number keys.
Tools: node tools/dem.mjs <city> (downloads GLO-30 tiles into data/dem/, writes data/dem/<city>/dem.bin and dem.json; env SIGMA=22 STEP=15). node tools/osm-build.mjs <city> <geojsonseq...> (picks up data/dem/<city>/ automatically; env DEM_DIR, ORIGIN, BBOX). node tools/check-city.mjs <city or folder> (exit 1 on a hard failure). node tools/brasov-report.mjs [geojsonseq] (places, sign and bear street tables). tools/city-config.mjs exports CITIES, cityParams(name), projection(origin). Exact rebuild commands are in docs/city-data-format.md. Brasov uses tools/city-config.mjs "trees" (wood 150 m2 per tree, 557k trees): the knob for forest density and frame rate. There are no tram lines in Brasov (rails 905 pieces, tram 0). Mountain trails exist as cls "foot" (93 pieces on the Tampa, 470 on Postavaru and Poiana).

### feat/actors (merged into main)
FILES: src/actors.js (exports class Actors), test/actors.mjs, 4 marked lines in src/main.js.
WIRING (main.js): import { Actors } from './actors.js'; const actors = await Actors.load('models/Xbot.glb', scene, city, { onMaterial: withCSM, max: LOWQ ? 60 : 120 }); actors.update(dt, player) each tick after traffic; 'actors,' in window.__game. Load options: onMaterial(mat) is called for every material created (pass withCSM so actors get shadows), max (default 120), events, seed, rng. Actors.load fetches Xbot.glb a second time (HTTP cache).
EVENTS: the manager emits through actors.events, else window.__game.events, else nothing. Payloads: 'hit' {target, dmg, by}, 'actor:down' {actor}, 'actor:tied' {actor}.
MANAGER API: actors.spawn(kind, {x,z}, opts) -> actor or null. opts: yaw, hp, persist (never culled or evicted), exact (skip the search for a free spot), scale, variant (thug: hood|beanie; civilian: plain|cap|beanie|scarf|bag|pack), fur (dog and bear colour). actors.list; actors.near(pos, r, filter) sorted nearest first and includes downed actors (filter them yourself); actors.walkTo(actor, x, z, speed) returns false if the actor is down, tied or stunned; state becomes 'run' when speed is above 2.6 (humans), 3.0 (dog), 3.2 (bear), 'walk' otherwise, and 'idle' on arrival; call it as often as you like, it only replans when the goal moves more than 2 m. actors.randomWalkPoint(pos, r) returns a plain {x, z} on a pavement, footway or pedestrian way, never on a carriageway and never inside a building or water. Also: actors.update(dt, player), actors.remove(a), actors.clear(), actors.setCity(city) for the map choice, actors.stats(), actors.blocked(x, z, r) (building or water test), actors.groundAt(x, z), actors.max, actors.onMaterial, actors.events.
ACTOR: id, kind, pos (Vector3, feet), vel, yaw (forward is (sin yaw, cos yaw); writable), hp, maxHp (thug 60, cop 100, civilian 30, dog 25, bear 220), state ('idle'|'walk'|'run'|'stunned'|'tied'|'down'), stunT, tied, mesh (Group already in the scene, position and yaw set by the manager), radius, height, speed, hasGoal, persist, removed, speedWalk, speedRun; methods hit(dmg, by) -> bool, stun(t) -> bool, tie() -> bool, remove(). tie() works from any live state (not only stunned), so the combat rules decide when it is allowed. hp 0 makes the actor 'down': it falls, lies 3.2 s, dithers out over 1.3 s, then is removed (actor.removed becomes true). Stun clears the goal; call walkTo again afterwards. Bones can be reached with actor.mesh.getObjectByName('mixamorigRightHand') to attach things (only the 22 kept bones exist, no fingers).
CULLING: actors beyond 160 m are taken out of the scene and frozen; beyond 420 m they are removed unless persist. Keep a reference and check actor.removed. Spawning at the cap evicts the farthest non-persistent actor beyond 160 m, else returns null.
TERRAIN: positions use city.groundAt?.(x, z) ?? 0 and obstacle heights are compared to the ground under them, so a hilly city should work, but that is not tested yet.
TEST: PORT=5212 node test/actors.mjs writes shots/actors-crowd.png and prints a COST line (ms per tick with and without actors, and per rendered frame).
